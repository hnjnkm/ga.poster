# Graphic Archive Workspace

Graphic Archive의 이미지와 한국어·영어·중국어 간체 설명을 한 화면에서 연결하고 편집하는 웹 도구입니다. 현재 버전은 **기존 CSV/XLSX 설명 가져오기 → 순번 연결 → 편집 → 원본 형식 내보내기**를 제공합니다.

## 실행

Node.js 24와 npm을 사용합니다. 현재 클라우드 체크아웃은 `/workspace/ga.poster`입니다.

```sh
npm ci
npm run dev -- --port 5173 --strictPort
```

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 현재 클라우드의 `/usr/bin/chromium`을 사용합니다. 다른 머신에서는 `playwright.config.ts`의 `executablePath`를 설치된 Chromium 경로에 맞추세요. 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃에서 작업하며, 별도의 Git worktree는 만들 필요가 없습니다.

## 사용 순서

1. `01.png`, `02.jpg`, `1002.png`처럼 숫자 이름의 이미지를 여러 개 불러옵니다. PNG, JPG, JPEG, WEBP, AVIF, GIF를 지원합니다.
2. 실제 Webflow 작업에 사용하는 UTF-8 CSV 또는 XLSX를 불러옵니다. 인코딩을 추측하거나 자동으로 변환하지 않습니다. XLS 파일은 지원하지 않습니다.
3. 워크시트, 제목 행, 순번 열, 세 언어의 설명 열을 선택하고 **이 열로 연결하기**를 누릅니다. 제안된 열도 직접 확인합니다.
4. 이미지 오른쪽의 언어별 설명을 수정합니다. 빈 셀, 줄바꿈, 공백, HTML 문자열도 편집할 수 있습니다. HTML은 실행하지 않고 원문으로 표시합니다.
5. **내보내기 → 검증 후 다운로드**로 원본 형식의 파일을 받습니다. Webflow에서 CSV를 업로드하는 작업이라면 해당 CSV 양식을 처음부터 사용하세요. XLSX를 Webflow용 CSV로 자동 변환하지 않습니다.
6. **작업 저장**은 이미지 원본, 원본 설명 파일, 열 연결, 편집 내용을 현재 브라우저의 IndexedDB에 저장합니다. 페이지를 다시 연 뒤 **저장한 작업 복원**을 누릅니다. 저장 중에는 편집을 잠급니다.

## 데이터 보존 규칙

- 이미지의 숫자 파일명과 명시적으로 지정한 순번 열만으로 연결합니다. 화면 위치·행 위치·설명 유사도로 연결하지 않습니다.
- `01`과 `1`은 같은 순번으로 연결합니다. 원본 셀과 파일명은 그대로 유지합니다. 이 규칙으로 중복되는 이미지/행이 있으면 편집 연결에서 제외하고 내보내기를 차단합니다.
- 공백이나 문자가 들어간 순번은 임의로 정리하지 않고 오류로 표시합니다.
- 화면은 순번 오름차순으로 표시하지만 파일의 행 순서는 바꾸지 않습니다.
- 원본 파일을 메모리에 별도로 보관합니다. 편집은 원본 행·열 좌표에 대한 변경 집합으로만 관리합니다.
- CSV는 변경한 필드의 토큰만 교체합니다. 다른 필드, 기존 따옴표, BOM, 구분자, 줄바꿈을 유지합니다.
- XLSX는 ZIP 내부에서 변경한 셀의 XML만 교체합니다. 다른 셀의 XML, 다른 시트, 스타일과 기타 ZIP entry의 내용은 유지합니다. 수정한 셀은 텍스트로 저장하며 해당 셀의 rich text 서식은 일반 텍스트가 됩니다. ZIP 재압축 때문에 수정한 XLSX 전체의 바이너리는 달라질 수 있습니다.
- 수정이 없으면 입력 파일과 동일한 바이트를 반환합니다.
- 다운로드 전에 결과 파일을 다시 읽어 모든 시트·행·셀을 원본 및 요청한 수정 내용과 대조합니다. 일치하지 않으면 다운로드하지 않습니다.
- 이미지가 없는 설명 행은 그대로 보존합니다. 원본에 순번이 없는 이미지는 미연결로 표시하고 해당 설명은 편집하지 않습니다.
- 수식·병합 셀은 편집을 차단합니다. 원본 순번이나 Webflow ID/Slug 등 다른 열은 편집 UI에서 변경할 수 없습니다.
- 지원 한도: 설명 파일 25 MB, 압축 해제된 XLSX 전체 100 MB, 20,000행, 256열, 100개 워크시트. XLSX의 한 셀은 32,767자까지 지원합니다.

## 현재 범위와 다음 단계

- 업로드와 편집·내보내기는 브라우저 안에서 처리하며 파일을 서버에 전송하지 않습니다.
- 로컬 저장은 현재 기기/브라우저에만 남습니다. 브라우저 데이터 삭제·저장 용량 제한에 영향을 받으며 서버 백업이나 동기화가 아닙니다. 중요한 결과는 파일로 다운로드해 보관하세요.
- 원본 행 수를 늘리거나 순번/열을 새로 생성하지 않습니다. 빈 양식으로 새 항목을 만드는 흐름은 실제 Webflow 템플릿을 받은 뒤 추가할 단계입니다.
- AI 분석·번역 API는 연결하지 않았습니다. 기존 작성 지침, 실제 열 구조, 사용할 모델 및 API 인증 방식을 받은 뒤 서버 측 생성과 결과 검토/적용을 추가해야 합니다. 생성 결과를 기존 설명에 자동으로 덮어쓰지 않는 흐름을 기본으로 합니다.
- 실제 사용자 파일로 Webflow 업로드를 검증한 것은 아닙니다. 현재 검증은 테스트용 다국어 CSV/XLSX와 1,000개 이미지 항목으로 수행했습니다.

## 검증

- 단위 테스트: 숫자 순번/중복/누락, CSV 원문 보존, XLSX 셀·ZIP 보존, 수식/병합 보호, 다국어 및 OOXML escape, 결과 변조 시 내보내기 거부.
- Chromium 기능 테스트: 파일 업로드, 순번 연결, 3개 언어 편집, CSV/XLSX 다운로드 대조, 중복 차단, 저장·새로고침·복원, 1,000개 항목, 모바일 가로 폭.

## 공개 배포

배포 대상은 GitHub Pages의 `https://hnjnkm.github.io/ga.poster/`입니다.

`main` 브랜치에 push하면 `.github/workflows/deploy-pages.yml`이 의존성 설치, 단위 테스트, `/ga.poster/` 경로용 빌드, Pages 배포를 순서대로 수행합니다. `gh run list --workflow deploy-pages.yml`로 실행 결과를 확인할 수 있습니다.

이미 원격 main에 있는 코드를 다시 배포할 때는 GitHub CLI 인증 후 다음 명령을 사용합니다. 로컬 수정 내용은 먼저 커밋하고 push해야 합니다.

```sh
npm run deploy
```

로컬에서 Pages용 빌드를 확인하려면:

```sh
npm run build -- --base=/ga.poster/
```

공개 사이트에서 기존 브라우저 검사를 실행하려면:

```sh
PLAYWRIGHT_BASE_URL=https://hnjnkm.github.io/ga.poster/ npm run test:e2e
```

정적 앱만 GitHub Pages로 배포합니다. 사용자 이미지·엑셀·브라우저 저장 데이터는 전송하지 않습니다. Netlify나 Vercel 토큰은 필요하지 않습니다. 앞서 환경 설정에 추가했던 VERCEL_TOKEN 항목 역시 이 배포와 무관합니다.
